🌐 B2B Identity Federation & Multi-Hop Token Architecture

How Keycloak Single Sign-On bridges into Microsoft Entra ID to mint dual tokens and enforce fine-grained delegation.
1. Single Sign-On at Corporate Keycloak (Identity Authority)
The human user (Alice, Bob, or Charlie) logs into Keycloak via 1-click login. Keycloak verifies corporate credentials and issues a signed Keycloak OIDC Bearer Token containing realm roles (admin, auditor, Storage Blob Data Reader) and client scopes (mcp:tool1, mcp:tool2, Mail.Send). The user has no password in Azure and never enters credentials twice.
2. B2B Identity Federation Bridge & Dual Token Issuance
The client/federation broker presents the Keycloak assertion to Microsoft Entra ID (RFC 7523 / SAML 2.0 Direct Federation). Entra ID validates Keycloak's cryptographic signature against Keycloak's published JWKS, maps Keycloak identity attributes to the tenant user, evaluates Claims-Mapping Policies, and mints an authentic Microsoft Entra ID User Subject Token (iss: login.microsoftonline.com/81f26b58..., scp, roles).
3. Scope Synchronization & Downscoping Governance
• Is Scope Synchronization Automated? In B2B federation, identity claims (roles/groups) sync via claims transformation and SCIM 2.0. Delegated scopes (like Mail.Send or mcp:tool1) are pre-consented via Tenant-Wide Admin Consent. When a user with the required role arrives, Entra ID authorizes the matching scopes.
• Why both scp and scope claims? Entra ID historically uses scp for delegated permissions; RFC 6749 standard uses scope. Both are provided for 100% compatibility with Microsoft SDKs and standard OAuth clients.
• Scope Carryover: Alice possesses Mail.Send, so Entra ID grants it. Charlie lacks Mail.Send in Keycloak and Entra ID, so Entra ID strictly excludes it — blocking unauthorized email dispatch at Step 4.
4. RFC 8693 Agentic Workload Delegation (Downstream Hops)
The Orchestrator receives the federated tokens, combines them with its SPIRE SVID (workload identity), and executes targeted token exchanges: Hop 3 to Azure Storage MCP (downscoped to mcp:tool1) ➔ Hop 4 JIT 60s user-delegation SAS ➔ In-Memory Redaction ➔ Hop 5 & 6 RFC 8693 OBO token exchange to Microsoft Graph for direct email delivery.
